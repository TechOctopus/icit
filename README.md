# icit

Управление вкладкой Chrome на ПК с телефона по Bluetooth, когда Wi‑Fi ПК не выпускает к ИИ‑сервисам.

```
 iPhone (Safari, сайт)                    ПК
 ┌────────────────────┐   Bluetooth PAN   ┌─────────────────────────────────────┐
 │ харнес + агент‑цикл│ ◄───────────────► │ bridge (Node, :8787)                │
 │ Claude API ───────►│  (hotspot iPhone) │   ws /ext  ◄──► расширение Chrome   │
 │  по сотовой сети   │                   │   ws /client   (телефон)            │
 └────────────────────┘                   │   POST /mcp    (Codex / Claude Code)│
                                          │                      │ scripting    │
                                          │                      ▼              │
                                          │                  вкладка браузера   │
                                          └─────────────────────────────────────┘
```

Как это обходит ограничение сети:

- Wi‑Fi ПК остаётся в закрытой сети. Bluetooth это отдельный интерфейс, одновременно с Wi‑Fi.
- iPhone раздаёт Personal Hotspot **по Bluetooth**. ПК подключается к нему и получает адрес `172.20.10.x`, телефон `172.20.10.1`. Между ними прямой IP‑линк.
- Мост на ПК отдаёт сайт‑харнес. Safari на телефоне открывает `http://172.20.10.x:8787`. Ставить на iPhone ничего не надо.
- К Anthropic API ходит только страница в Safari, через сотовую сеть телефона. ПК не делает ни одного запроса к ИИ и не видит API‑ключ.
- Web Bluetooth в Safari на iOS отсутствует, поэтому «сырой» BLE из сайта невозможен. Bluetooth PAN это единственный путь без установки приложения.

## Состав

| Папка | Что это |
|---|---|
| `extension/` | Chrome MV3 расширение. Держит WebSocket к мосту, исполняет инструменты во вкладке. |
| `bridge/` | Node‑сервер на ПК. Маршрутизирует вызовы инструментов, отдаёт сайт для телефона, даёт MCP‑endpoint. |
| `bridge/web/` | Сайт‑харнес для телефона: чат, настройки, агент‑цикл на `@anthropic-ai/sdk`. |
| `bridge/src/tools.js` | Единственное место, где описаны инструменты. Расширение их исполняет, харнес и MCP их публикуют. |

Инструменты: `tabs_list`, `tab_select`, `tab_open`, `page_navigate`, `page_back`, `page_snapshot`, `page_click`, `page_type`, `page_press`, `page_scroll`, `page_read`, `page_screenshot`, `page_eval`.

`page_snapshot` возвращает текстовый слепок страницы с нумерованными `[ref]` для интерактивных элементов. Это основной способ «видеть» страницу: дёшево по трафику через Bluetooth. Скриншот есть, но это JPEG и он медленнее.

## Запуск

### 1. Мост на ПК

```bash
cd bridge
npm install
npm start          # собирает web/dist/app.js и поднимает http://0.0.0.0:8787
```

Переменные окружения:

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `ICIT_PORT` | `8787` | порт |
| `ICIT_HOST` | `0.0.0.0` | интерфейс прослушивания |
| `ICIT_TOKEN` | пусто | общий секрет для `/client`, `/api/call`, `/mcp`. Вводится в настройках сайта на телефоне. |
| `ICIT_CALL_TIMEOUT_MS` | `90000` | таймаут одного вызова инструмента |

В логе мост печатает адреса, по которым его видно снаружи. Нужен тот, что на Bluetooth‑интерфейсе, обычно `172.20.10.x`.

### 2. Расширение в Chrome

`chrome://extensions` → Developer mode → Load unpacked → папка `extension/`.
Бейдж `on` на иконке означает, что расширение подключилось к мосту. В попапе можно закрепить целевую вкладку кнопкой «Use current tab as target». Без этого инструменты работают с активной вкладкой.

### 3. Bluetooth‑линк iPhone ↔ ПК

На iPhone: Настройки → Режим модема → «Разрешать другим». Bluetooth включён.

Windows: Параметры → Bluetooth → добавить iPhone (подтвердить код на обоих). Затем Панель управления → Устройства и принтеры → правый клик по iPhone → «Подключаться через» → «Точка доступа». Появится сетевой адаптер «Bluetooth Network Connection» с адресом `172.20.10.x` (`ipconfig`).

macOS: Системные настройки → Bluetooth → подключить iPhone. Затем в меню Bluetooth у iPhone «Подключиться к сети». Адрес смотреть в Сеть → Bluetooth PAN.

Linux (NetworkManager/bluez): спарить iPhone в настройках Bluetooth, затем

```bash
nmcli device wifi   # Wi‑Fi не трогаем
nmcli connection add type bluetooth con-name iphone-pan bt-type panu bdaddr <MAC iPhone>
nmcli connection up iphone-pan
ip addr show bnep0
```

Если интернет на ПК через телефон не нужен (например, чтобы ПК по‑прежнему никуда не ходил кроме закрытой сети), убирается маршрут по умолчанию через Bluetooth‑интерфейс, остаётся только подсеть точки доступа:

```bash
# Linux
sudo ip route del default dev bnep0
# Windows (PowerShell, admin): найти InterfaceIndex у "Bluetooth Network Connection"
Get-NetRoute -DestinationPrefix 0.0.0.0/0 | Where-Object InterfaceAlias -like "*Bluetooth*" | Remove-NetRoute
```

Подсеть `172.20.10.0/28` остаётся доступной, этого достаточно для связи телефон ↔ мост.

### 4. Сайт на телефоне

Открыть в Safari `http://172.20.10.<x>:8787/` (адрес ПК из шага 3). ⚙︎ → вставить Anthropic API key → Сохранить. Две зелёные точки в шапке: мост и расширение на связи. Можно добавить на экран «Домой», страница работает как standalone.

Кнопки `snap` и `shot` показывают слепок и скриншот вкладки без обращения к модели. Это удобно, чтобы проверить линк.

Дальше обычный чат: «открой документацию по X и найди раздел про Y», «заполни форму на странице», «прочитай, что написано в ошибке». Модель вызывает инструменты, вызовы и результаты видны в чате сворачиваемыми блоками.

Модель по умолчанию `claude-opus-5-5`, effort `medium`. Ключ хранится в `localStorage` Safari, на ПК не передаётся.

## MCP для Codex / Claude Code

Мост одновременно является MCP‑сервером (Streamable HTTP, stateless). Любой MCP‑клиент, который по IP достаёт до моста, получает те же 13 инструментов:

```bash
# на самом ПК
codex mcp add icit --url http://127.0.0.1:8787/mcp
claude mcp add --transport http icit http://127.0.0.1:8787/mcp

# с другого устройства на Bluetooth‑линке (например Android + Termux)
codex mcp add icit --url http://172.20.10.2:8787/mcp
```

Если задан `ICIT_TOKEN`, добавить заголовок `Authorization: Bearer <token>` или `?token=<token>` в URL.

Плоский HTTP без MCP:

```bash
curl -XPOST http://127.0.0.1:8787/api/call -d '{"tool":"page_snapshot","args":{"maxChars":2000}}'
```

## Безопасность

- `/ext` принимает только соединения с `127.0.0.1`. Чужое устройство в сети не может притвориться расширением.
- Остальные endpoint'ы слушают на всех интерфейсах, чтобы телефон их видел. На Bluetooth‑линке кроме телефона никого нет, но при `ICIT_HOST=0.0.0.0` мост виден и в Wi‑Fi сети ПК. Для такой ситуации задать `ICIT_TOKEN` или `ICIT_HOST=172.20.10.<x>`.
- Расширение имеет `<all_urls>`: оно исполняет действия в любой вкладке, которую укажет мост. Это и есть назначение, но держать мост стоит только пока он нужен.
- `page_eval` исполняет произвольный JS в контексте страницы. Модель получает его как инструмент, система подсказывает останавливаться перед логином, оплатой и деструктивными действиями.

## Ограничения и что дальше

- Скорость Bluetooth PAN около 1–2 Мбит/с. Текстовые слепки летают, скриншоты по 100–200 КБ занимают секунду.
- Service worker MV3 держится живым пингом каждые 20 с и будильником раз в 30 с. Если Chrome его выгрузит, переподключение займёт до 30 с.
- `page_eval` блокируется строгим CSP на части сайтов. Замена через `chrome.debugger` возможна, но показывает плашку «браузер управляется».
- В харнесе нет стриминга текста в UI: ответ появляется целиком после завершения хода. Стриминг под капотом используется, чтобы длинные ходы не упирались в HTTP‑таймаут.
- Нет сохранения истории диалога между перезагрузками страницы.
